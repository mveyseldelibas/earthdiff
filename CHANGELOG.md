# Changelog

All notable changes to this project are documented here. Format: [Keep a Changelog](https://keepachangelog.com/), versioning: [SemVer](https://semver.org/).

## [Unreleased]

### Fixed
- QGIS plugin 0.1.3: passes the Qt 6 check of plugins.qgis.org (scoped enums also in the QGIS 3 fallbacks); `supportsQt6` removed from the metadata, `qgisMaximumVersion=4.99` is what marks QGIS 4 support. The metadata now has the contact e-mail the plugin repository requires.
- QGIS plugin 0.1.1: the drawn rectangle was hard to see (QGIS's own extent tool draws a faint outline). The plugin now draws it itself while dragging and afterwards; Esc cancels a drag. From 0.1.2 the outline is black on a white halo, readable on any base map and unlike every result colour (the orange of 0.1.1 was the colour of vegetation loss).
- QGIS plugin 0.1.2: after an analysis the panel and the map could not go back to how they were. A "New analysis" button now clears the drawn area and the result; it and closing the panel ask whether to remove that panel's result layers (the files stay in the output folder) and go back to the earlier map view.

## [0.2.1] - 2026-11-13

### Added
- **QGIS plugin** (`qgis/earthdiff_qgis`, QGIS 3.28+ and QGIS 4 / Qt 6, Turkish and English): a panel to pick the area (map view, drawn rectangle or selected polygons, size checked against the 2,000 km² limit) and the dates (a month against the same month of an earlier year), plan or run, and get the change polygons, class raster and before/after images back as styled layers, with every warning and the data attribution in the panel. It runs the earthdiff program of a normal Python installation or `uvx` without QGIS's own Python / GDAL / PROJ environment, so nothing is installed into QGIS. Zip: `python scripts/build_qgis_plugin.py`.
- `before.tif` and `after.tif`: the true-colour before/after images as georeferenced RGBA GeoTIFFs on the analysis grid (same grid as `change_class.tif`), for GIS software; also listed in the MCP result (`before_tif`, `after_tif`).

## [0.2.0] - 2026-11-11

### Added (second round)
- **`likely_cause` for vegetation loss** (`fire-like` / `clearing-like` / `unclear`, a hint with measurements and a stated basis, not a new class): reads Sentinel-2 B12 (optional: an unreadable B12 never blocks a run), NBR / dNBR with the Key & Benson (2006) severity thresholds also used by Copernicus EFFIS, plus post-event brightness and outline shape (these two thresholds are this project's own, set on two public cases). In `changes.geojson`, `summary.json`, `report.html` (card, popup, table column), the CLI summary (`--no-likely-cause` turns it off) and the MCP answer. Checked on Manavgat 2021 (3,075 of 3,119 ha fire-like) and Istanbul Airport 2017 to 2019 (8.6 of 558 ha fire-like, a recorded miss).
- **Seasonal check** (`--seasonal-check`, MCP `seasonal_check`, off by default): compares vegetation-loss polygons with the same windows of 2 earlier years and flags `likely_seasonal`; polygons are never removed. Measured +46 s on a 39 km2 Konya plain test; `plan_change` reports the extra windows and the cost.
- **Bright-surface warning**: when at least 20 % of the comparable area is very bright, non-vegetated surface (salt, sand, snow), the answer says change there is not reliable, caps the confidence at low, grades data quality poor and lowers the confidence of polygons on bright pixels. Reports the NDWI water-like share of the bright pixels before and after as an exploratory wet/dry signal.
- `explain_method` topics `likely_cause`, `seasonal`, `bright_surfaces`; `validation/mcp_questions.md` now covers Manavgat, Lake Mead, Istanbul Airport, Konya plain (with and without the seasonal check) and Lake Tuz (late summer and spring baseline, index experiment `validation/tuz_experiment.py`).

### Added
- **MCP server** (`earthdiff-mcp`, also `earthdiff mcp`; stdio; install with `pip install "earthdiff[mcp]"` or `uvx --from "earthdiff[mcp]" earthdiff-mcp`) so that AI assistants (Claude Desktop, Claude Code, Cursor, any MCP client) can answer "what changed here?" with free Sentinel-2 imagery, no account or API key.
- Tools: `find_place` (OSM Nominatim: identifying User-Agent, at most 1 request/s, on-disk cache, attribution; ambiguous names return candidates instead of a guess; oversized boxes come with narrowing options), `plan_change` (scene counts and warnings without downloading), `detect_change` (hectares and polygons per class, comparable share, confidence, data quality, largest areas, all warnings; before/after/change-map images returned as MCP image content; `report.html` and `changes.geojson` written locally; progress notifications and a heartbeat for long runs), `explain_method` (rules, pipeline, confidence, limits, data).
- Safety: unknown tool parameters are rejected; output confined to `EARTHDIFF_OUTPUT_DIR`; `name` sanitised; configurable area (`EARTHDIFF_MAX_AREA_KM2`, default and maximum 2,000) and run-time (`EARTHDIFF_MAX_RUNTIME_S`) limits; one analysis at a time; error messages are scrubbed of file paths; scene URLs are checked against a Sentinel-2 host allow-list; nothing is written outside the output folder and no existing file is ever deleted (only an empty run folder created by a failed run is removed).
- `pipeline.plan()` accepts an injectable `search` and reports scene cloud cover; `pipeline.period_warnings()` shared by the CLI and the MCP server.
- Tests: fake STAC / raster / Nominatim unit tests, a real MCP stdio test (`tools/list`, `tools/call`, images, progress, strict arguments, redaction) and a `network`-marked end-to-end test against the live services.
- `validation/run_mcp_questions.py` and `validation/mcp_questions.md`: real questions asked through the MCP server (Manavgat wildfire 2021, Lake Mead 2019 vs 2022, Lake Tuz 2019 vs 2021) with sources and honest caveats.
- `server.json` (MCP Registry), a PyPI trusted-publishing workflow and a CI workflow (Linux 3.11 and 3.13, Windows 3.12; network tests deselected).
- The MCP server reports its version in `initialize` (mcp 2.x).

### Changed
- Version 0.2.0; `mcp` extra added; `python_requires` unchanged.
- A change share above 30 % of the area is no longer treated as a data mismatch when at least 80 % of the changed area is fire-like vegetation loss (dNBR): the warning says the share fits one large burn and the MCP `data_quality` is not lowered for it. Found on a 98 km2 box inside the 2021 Manavgat scar, which was graded poor.
- One area limit everywhere: 2,000 km2 in the CLI, `watch`, the web UI and the MCP server (`aoi.MAX_AREA_KM2`; was 400). Larger areas are read at 20/30/60 m.
- Report map: every change is described in plain words (what changed, the likely cause, and whether it is a strong, moderate or weak change) in a hover/tap tooltip, the popup and the table; outlines are drawn by strength (weak ones dashed). Changes too small to see at the current zoom are also marked with a dot (solid = strong, half = moderate, hollow = weak) so none is missed. The legend states the smallest change mapped.
- Web UI: "Smallest change to show" (0.1 / 0.5 / 2 ha).
- Report and web UI in **Turkish and English** (TR / EN switch; Turkish browsers start in Turkish; the choice is remembered). Warnings, the method section and the likely-cause hints have Turkish versions (`earthdiff/i18n.py`); a test checks that every pipeline warning is translated.
- Report **scene by scene** timeline: every satellite pass used (before and after) as its own frame, in date order, with play / pause, a slider and arrow keys; the date, period and clear share of each frame are shown live. The changes stay marked (and pulse) on every frame. Each frame shows only what that pass saw clearly: cloud, cloud shadow, snow and gaps are left transparent (not filled from other dates); passes showing less than 30 % of the area are left out of the timeline.
- Swipe is a **time cursor**: the whole line can be dragged (not only the knob); it sits between two consecutive satellite passes, the left side shows the earlier pass, the right side the later one, and both dates follow the line live. The changes stay marked on both sides.
- Choosing a basemap fades the satellite image out (a "Satellite" opacity slider blends them), so the basemap shows inside the analysed area too; basemaps are drawn only inside the drawn area, which stays cut out, in 2D and in 3D (in 3D the OpenStreetMap / OpenTopoMap tiles are draped on the terrain when online; the relief always works offline).
- 3D markers: rings lie on the terrain around the main changes; when zoomed in, small changes stand as pins on the ground; the selected change blinks.
- Table and map are linked: click a row to fly to the change (it blinks and its popup opens); click a change on the map (2D polygon or dot, 3D pin) and its row lights up. The table scrolls on its own so the page does not jump.
- **In-between years**: when the before and after windows are years apart, the timeline gets one small frame per in-between year (same season as the after window, the clearest pass, read from the COG overviews; at most 10; `--no-yearly-frames` skips them). They are for viewing only and do not change the analysis.
- **Old events are no longer washed out**: when the windows are years apart, each vegetation-loss polygon is followed through the in-between years (NBR, NDVI and brightness of one pass per year, read with the timeline frames). The largest one-year NBR drop is taken as the event; if it is clearly larger than the end-to-end drop (the area has partly recovered, as a burn scar does in a few years), the likely cause is judged on that step and the polygon gets `event_before`, `event_after` and `event_dnbr`. The report, its tooltips and the Excel sheet say when the largest drop happened. Found on Manavgat 2020 vs 2024, where the 2021 burn had regrown enough to look "unclear". Checked on Manavgat 2020 vs 2024 (fire-like 159 -> 4,454 ha; 4,674 ha dated to the 2021 step) and North Evia, Greece 2020 vs 2024 (2,082 ha fire-like, the main loss dated between 27 Jul 2021 and 18 Aug 2022, around the August 2021 fire). A year with no clear pass (cloud, smoke) is retried with its window widened by a month on each side.
- **Excel export**: `changes.xlsx` in the output folder (sheets: summary with totals and warnings, one row per change with a plain-language description, numbers as numbers and an OpenStreetMap link, scenes), written without extra dependencies; the report's Excel button downloads it in the language shown (Turkish or English), and a Print / PDF button prints the report. The MCP answer lists the workbook.
- **Different seasons are refused** (CLI, web UI, MCP): when the two windows are more than 60 days apart in the yearly cycle the run stops with an explanation (winter vs autumn made almost everything look changed: snow, low sun, leaves, crops); 45 to 60 days still runs with a warning; the CLI can override with `--any-season`. In the web UI "before" is now a year (same month as "after"), so a different season cannot be picked.
- Web UI: the basemap is chosen on the drawing page (satellite only, relief, OpenStreetMap, topographic), shown there on the drawing map and used by the report (`report.html#base=topo`). On the drawing map "satellite only" is the cloudless Sentinel-2 mosaic of 2023 (EOX) and "relief" is shaded by the local server from the open AWS Terrain Tiles; the report keeps its own images and its embedded Copernicus DEM relief. The 2D / 3D switch is in the report only.
- Report: the changes and scenes tables have a search box (number, change, strength, cause, place; scenes by period, id, date) and are paged (10 / 25 / 50 / 100 rows per page) and list every change, not only the largest 300; picking a change on the map turns the table to its page; printing lists every row.
- 3D: the before/after swipe works (the left of the line shows the earlier pass, the right the later one); no basemap choice in 3D (the satellite image on the embedded relief, as before); the labels name in-between frames.
- One window-length limit everywhere: each time window may span at most 366 days (was enforced only by the MCP server); the two windows may still be years apart.
- Animated pulse rings on the largest and strongest changes (toggle) so they are easy to spot.
- Basemap choice and an **offline 3D view**. During the run a small window of the Copernicus DEM GLO-30 (30 m, public COGs on AWS) around the area is read (about 1 to 2 s; `--no-terrain` skips it) and embedded: a relief basemap (offline) and a WebGL terrain with the satellite image (before, after or the timeline frame) draped on it, a dot on every change and pulse rings on the main ones, click a dot for what changed, drag to rotate, wheel or pinch to zoom, height exaggeration x1 to x5. The report needs no internet for any of this; only the optional OpenStreetMap and OpenTopoMap basemaps load online.
- Web UI (`earthdiff ui`): areas up to 2,000 km2. An oversized area now shows a red warning, colours the shape red and the Run button says why it is disabled; the server enforces the same limit. While drawing, the size is shown live next to the cursor (red over the limit) with a thicker outline; polygons can be finished with Enter, Backspace removes the last point, Esc cancels.

## [0.1.0] - unreleased

### Added
- `earthdiff run`: AOI (GeoJSON or bbox) + two time windows -> report folder
  (`report.html`, `changes.geojson`, `before.png`, `after.png`, `change_map.png`, `overview.png`, `change_class.tif`, `summary.json`).
- Free Sentinel-2 L2A access without account or key: Element84 Earth Search (default) and Microsoft Planetary Computer (optional), windowed COG reads only.
- SCL cloud / shadow / snow masking, per-period median composites, scene selection by real cloud-free AOI coverage.
- Explainable rules on NDVI, MNDWI and BSI: vegetation loss / gain, new water / water loss, new bare soil / built-up; MMU, morphological cleanup, polygonization, hectares, heuristic confidence.
- Guard rails: AOI size limit, minimum cloud-free fraction, seasonal-mismatch / single-scene / implausibly-large-change warnings.
- Self-contained HTML report: before/after swipe, change map, clickable polygons with before/after crops and index values, sortable table, method and caveats.
- `earthdiff plan` (dry run), `earthdiff watch` (monthly re-runs from TOML, history CSV; you schedule it), `earthdiff ui` (local drawing UI on 127.0.0.1).
- pytest suite with synthetic rasters; one `network`-marked STAC smoke test.
- Validation cases in `validation/` with honest notes.
